# SA 演示手册

## 场景故事

场景包含五位共用项目 Agent 的分析师，任务是完成客户流失（churn）分析。

- Alice 偏好简洁、SQL 优先的回答。这条偏好只应成为 Alice 的个人记忆。
- Bob 发现经过治理的营收视图（curated revenue view）排除了已退款订单。这条发现可能
  对所有人都有价值，但必须先经过评估才能成为共享记忆。
- 官方的指标定义仍然保留在托管的 Knowledge Base 中。
- 一套可复用的营收校验流程最终会被提升为一个 Skill。

## 演示步骤

1. Alice 提出分析请求，并说明："Prefer SQL first and keep explanations
   short."。Agent 以 actor `user:<alice-sub>` 将该完整回合写入个人记忆（Personal
   Memory），偏好提取策略会异步完成抽取。
2. Bob 运行一个工具验证退款排除逻辑，并基于
   `contracts/memory-candidate-proposed.json` 提交经过脱敏的候选记忆。
3. EventBridge 启动 Standard 类型的 Step Functions 执行。
4. 状态机在 `WaitForHumanReview` 处暂停；评估人收到的是候选 ID，而不是任务令牌
   （task token），也不是原始对话内容。
5. 评估人在可观测性平台中查看证据并批准。
6. 评估人 API 调用 `SendTaskSuccess`。工作流将批准后的文本直接写入
   `/projects/project:analytics-poc/shared/` 命名空间（namespace），作为长期共享记忆
   （Shared Memory）记录。候选 ID 即其幂等键；不会有第二次模型抽取来改写已批准的
   表述。
7. Carol 开启一个新会话。Agent 检索到：
   - 来自 Knowledge Base 的官方指标定义；
   - 来自共享记忆的、已批准的退款注意事项；
   - Carol 自己的偏好，而不是 Alice 的偏好。
   `ContextBuilder` 将这些来源保存在彼此独立的字段中，提供明确的优先级规则，并把
   记录 ID、命名空间、相关性得分和策略 ID 一并作为引用信封（citation envelope）
   带上。
8. 将该共享记录标记为 `procedure_hint`。针对
   `skills/validate-revenue-metric/SKILL.md` 提交一个 Git 变更；经过评审和测试后，
   该 Skill 成为可执行的权威来源。

## 预期的 Step Functions 视图

```text
RegisterCandidate
  -> CandidateEligible?
  -> WaitForHumanReview [Running]
  -> Approved?
  -> PublishSharedMemory
  -> MarkPublished
```

因隐私原因被拒绝的候选会走 `MarkRejected` 路径，全程不会暴露给共享 Memory 资源。

## 脚本化场景与测试报告

`run_validation.py` 只断言四项布尔型能力检查。`run_demo_scenario.py` 则针对真实
AWS 环境完整演绎整个故事，并输出一份带叙述的报告：

```bash
python3 poc/run_demo_scenario.py --deployment build/poc-deployment.json
```

它会生成 `docs/scenario-test-report.md`（叙述式报告，包含每一条 prompt、回答和记录
ID；中文版报告见 `docs/实验报告.md`）以及 `build/scenario-results.json`（机器可读的
步骤数据）；任一检查失败时以非零状态码退出。

五幕、十四项检查：个人记忆的连续性与偏好抽取；一个用户无法读取另一个用户的记忆；
策略闸门在任何人看到之前就拦下了一个置信度 0.98 但分类受限的候选，以及一个置信度
0.35 的候选；人工评估环节包括匿名请求返回 401、任务令牌不外泄、逐字发布、重放请求
返回 409 以及拒绝行为的审计；最后是一位新人引用了几分钟前刚被批准的记录，同时没有
继承任何他人的个人记忆。

有两个值得保留的断言陷阱。在共享命名空间中等待"任意一条记录"会因为此前运行留下的
记录而误判通过，因此第 5 幕等待的是第 4 幕中发布的那个特定 `memoryRecordId`。同理，
当抽取从未真正运行时，"Bob 什么也看不到"会空洞地通过，因此第 2 幕还会断言 Alice 的
命名空间非空。

## 治理仪表板（Governance Dashboard）

```bash
python3 dashboard/server.py --deployment build/poc-deployment.json --port 3000
```

打开 `http://localhost:3000`。该服务仅绑定 `127.0.0.1`，并使用运维人员本地的 AWS
凭证发起只读的 Memory 调用，因此浏览器端永远不会拿到 AWS 凭证，也不会读取
DynamoDB。评估决策则由浏览器直接发往受 Cognito 保护的 Review API，该 API 会在每次
请求时重新校验项目评估人组的成员身份。

| 视图 | 展示内容 | 数据来源 |
|---|---|---|
| Personal Memory | actor 与 session 选择器、带解析回合的短期事件、抽取出的偏好、会话摘要 | `ListActors`、`ListSessions`、`ListEvents`、`ListMemoryRecords` |
| Shared Memory | 固定的项目命名空间、清单浏览与语义检索分开呈现、每条记录附带 ID、命名空间、得分、策略 ID 与元数据 | `ListMemoryRecords` 对比带 `project_id` 和 `review_status` 过滤条件的 `RetrieveMemoryRecords` |
| Review Queue | 按状态列出候选，附证据引用、提交人以及已发布的共享记录 ID；可对待处理项批准/拒绝 | 携带 Cognito ID token 的 `GET`/`POST /reviews` |

`reviewerOrigin` 必须与仪表板的 origin 完全一致，因为评估人 Lambda 会把该值原样返回
在 `access-control-allow-origin` 中。

登录需要一个属于堆栈输出的项目评估人组的 Cognito 用户。请使用与
`run_validation.py` 所用账号不同的账号，因为验证脚本每次执行都会轮换它自己的评估人
密码：

```bash
aws cognito-idp admin-create-user --user-pool-id <ReviewerUserPoolId> \
  --username <you@example.com> --message-action SUPPRESS
aws cognito-idp admin-set-user-password --user-pool-id <ReviewerUserPoolId> \
  --username <you@example.com> --password '<password>' --permanent
aws cognito-idp admin-add-user-to-group --user-pool-id <ReviewerUserPoolId> \
  --username <you@example.com> --group-name <ReviewerGroupName>
```

页面顶部的标题行会显示该 token 携带了哪些组，并在账号不在评估人组内时给出警告，
因为此时 API 会返回 403。

跨桌面、笔记本和移动端视口的布局与功能回归检查：

```bash
REVIEWER_EMAIL=<reviewer> REVIEWER_PASSWORD=<password> \
  node dashboard/check_layout.mjs
```

只要出现任何元素重叠、横向溢出或控制台报错，它就会失败，并把截图写入
`build/dashboard-screenshots/`。

## 生产环境扩展

- 对于 Strands Agent，使用 `AgentCoreMemorySessionManager` 承担常规的个人回合持久化，
  让 `TurnRecorder` 专注于经过脱敏的治理事件。
- 用面向具体工作负载的 Bedrock Guardrail 策略，在存储前对用户输入设卡，并在注入
  prompt 前对召回的记忆设卡。
- 对于必须留在短期记忆、但不应产生个人长期记录的工具、系统、调试、导入及敏感事件，
  标注 `extractionMode="SKIP"`。
- 增加一个评估人 Web 应用，提供候选内容 diff、证据深链以及项目成员授权。
- 为 Knowledge Base 文档 PR 和 Skill PR 使用一次性的提升队列。
- 增加针对信息泄漏、陈旧记忆冲突以及检索归因的自动化评测。
- 增加隐私请求的删除传播能力，覆盖日志、记忆、文档和向量索引。
- 当下游生命周期消费方的价值足以证明 Kinesis 的成本与暴露面时，再启用
  `METADATA_ONLY` 记录流；并确保消费方是幂等的。
- 只有在明确定义了 RTO、RPO 和数据驻留要求之后，才引入跨区域双写／记录复制。
