## 定位结论

共享记忆的主要工程难点在于何时、由谁将经验写入共享层。本项目在写入边界建立准入治理：
结构化提案 → 策略闸门 → 人工审核 → 逐字入库 → 可归因、可撤销。

Knowledge Base 与 Skills 承载完成治理并趋于稳定的下游知识制品。

## 按三类能力分析差异

将「记忆治理」拆分为授权、准入和维护，可以区分已有能力、项目差异和当前缺口。

| 格 | 问的问题 | 行业现状 | 本项目 |
|---|---|---|---|
| 授权 Authorization | 谁有权写共享域 | 已解决，不新颖 | IAM 条件键 + 双 Memory 资源 |
| 准入 Curation | 这条事实够不够格被共享 | **全行业空白** | 差异化在这里 |
| 维护 Maintenance | 这条事实还是不是真的 | 有自动化实现，被证明不可靠 | 当前缺失 |

### 授权：已有成熟控制

Zep 的 ABAC（策略绑定 API key，写权限 fail-closed）、Cognee 的数据集级 ACL、Databricks
Unity Catalog 都已经做了这一格（均未核实）。本项目用 IAM 条件键加双 Memory 资源实现，这是
工程上合理的选择，但不构成项目差异。

### 准入：主要差异所在

支撑「准入是空白」的引文（均未核实）：Letta 称 "when a block is shared, all attached agents
can read and write to it"；Databricks 称 "Scope is the isolation boundary between users.
Configure the scope in trusted code, and never let the model set it. The app service
principal can read every scope."；Microsoft Foundry 最佳实践称 "Avoid giving agents access
to memories shared across all users"；Anthropic Claude Code 的 `CLAUDE.md` 团队共享走源码
评审，自动记忆明确 "just you"；一篇 vendor-neutral 协议论文（arXiv:2606.01138）称 "no
framework ships a governance surface that lets a human review writes before they enter
long-term storage"。

这些材料共同指向的形状是：共享是**权限问题**，写入内容本身没有闸门。

### 维护：人工闸门的适用理由

这一格给出的是比安全理由更强的论证（均未核实）：STALE 基准（arXiv:2605.06527）称前沿模型
配专用记忆框架，识别「自己的记忆已失效」最高 55.2%；Zep 的 Fact Invalidation 是唯一
shipped 的失效方案，但判定是一次 LLM 调用，与写入同属一个可靠性等级；mem0 自承 Memory
Decay 是 "a ranking bias, not truth maintenance"。

推论：**自动化维护不可靠，所以需要人。** 这比「因为不安全所以要审核」好用，因为它不依赖
攻击者假设。

## 2026 年的反向趋势

| 产品 | 时间 | 做法 |
|---|---|---|
| Anthropic Claude Tag | 2026-06 | "Memory generated in public channels is shared across the workspace automatically"；管理员只能事后删 |
| Microsoft procedural memory | Build 2026 | 有 CRUD 界面，无审批 |
| TencentDB Agent Memory「Team Memory」 | 2026-08 | per-item owner/version/status/usage-history，且开源 |

（三条均未核实。）TencentDB 那条最值得注意：它把 status 做进了记录本身，正是本项目缺的
维护那一格。

调研材料显示行业方向偏向「**先共享、事后补救**」，本项目采用「先审批」。这一差异需要
单独论证，不能仅以不同于主流作为合理性依据。

## 差异主要来自捕获成本，而非审批流程

当前文档把创新说在「治理／审批／提交」上，而审批是三格里最不新的一格 —— 本项目自己的
[设计取舍依据](设计取舍依据.md)就承认候选状态机 near-isomorphic 于 AgentCore Registry。

本项目将 agent 记忆问题进一步分析为知识贡献的激励结构问题。

理论侧（均未核实）：Cabrera & Cabrera《Knowledge-Sharing Dilemmas》(Organization Studies
23(5):687–710, 2002) 称知识贡献是公共品困境，"there tends to be under-supply of
contributions in social dilemma situations"；Wasko & Faraj《Why Should I Share?》(MIS
Quarterly 29(1):35–57, 2005) 称贡献由互惠／声誉／网络承诺驱动，不由 artifact 的存在驱动 ——
即**把 KB 和 Skills 建好了，不会有人往里写。**

实证侧（均未核实）：Agent READMEs（arXiv:2511.12884）统计 1,925 个仓库的 2,303 个 context
文件，"maintained through frequent, small additions"，覆盖率 build 62.3%／实现 69.9%／架构
67.7%，但 security 14.5%／performance 14.5% —— 团队只写让 agent 跑起来的东西，不写来之不易
的判断。Skills 浅层采用（arXiv:2602.14690，2,923 仓库）称 Skills "used predominantly as
static documents rather than executable workflows"。Stack Overflow 月提问量 2014-03 峰值
207,204 → 2026-07 约 1,442（约 −99.3%）。从业者给的根因是两句话："nothing breaks when it's
stale, so the gap grows silently"、"the update has no natural trigger"。

成功迭代的案例只靠一类手段：同 PR 门禁、事故触发、定期 ablation 或 GC agent 提议删除 ——
**全是「在上下文最热的时刻降低贡献成本」。**

建议表述：KB 和 Skills 已解决存储与检索问题，剩余缺口是**缺少自然的写入触发点**；公共品
困境会进一步降低无触发机制时的贡献率。捕获触发器决定贡献是否发生，审批流负责建立可信度。

## 文档需要回应的四项反驳

### 一、「陈旧且自信」比「不存在」更糟

"a stale AGENTS.md is worse than no AGENTS.md"（未核实）。所以「不完美地捕获 vs 完全丢失」
**不能据此自动判定前者更优**。

机制解释（逻辑独立成立，不依赖引用）：向量相似度度量主题相关性，不度量时间相关性。18 个月
前的定价页与今早的更新，对 cosine 而言无法区分；且旧文档可能因为写得更详尽而**得分更高**。

### 二、退出机制

共享层是预备区，预备区里的东西应该走掉（论证见[为什么按写入权威分层](为什么按写入权威分层.md)）。

**现状与原判断的两处更正：**

- 原分析引用的 event-expiry 能力是**事实错误，已修正**（README 与 roadmap 两对都已改）。
  已核实 `MemoryRecordCreateInput` 的成员只有
  `['content', 'memoryStrategyId', 'namespaces', 'requestIdentifier', 'timestamp']`，无
  expiry 字段。
- 原分析称「索引键现在加不进去，所以取代机制被卡住」，这个前提**是错的**。索引键确实在
  CreateMemory 时固定、事后不可添加，但 `review_status` 本来就已经是索引键，检索侧本来就在
  按它预过滤 —— 取代机制并不需要新键。真正缺的只有 `superseded_by` 一个，现已在
  `infra/lib/memory-governance-stack.ts` 声明（仅对新建 Memory 生效）。

**仍未做**：取代机制本身的实现。

### 三、准入闸门管不了去重

本仓库实测：共享层 4 条记录里 2 条是同一句话（`mem-5f417b6c` 与 `mem-d9d4444b`），相关度
分数同为 0.6626。闸门管「够不够格」，**天然管不了「是不是已经有了」**。（**本仓库实测**，可引。）

**现状**：限制章节已前移，并补入此条。闸门去重仍未实现。

### 四、审核者产出与疲劳

以下是本文两条**已核实**的引用：原页面已抓取，每个子主张均已逐字核对。

- arXiv:2607.02579，*When Not to Write Memory: Governing False Promotion from Correlated
  Agent Traces*（Yijiashun Qi, Xiang Xu, Yuxuan Li）。**已核实**：false promotion
  0.371→0.032；133 条外部候选中人工裁决认为**没有一条**适合自动晋升；11 条 verification-gate
  positives 全部被驳回。
- arXiv:2606.22721，*Habituation at the Gate: Rising Approval and Declining Scrutiny in
  Human Review of AI Agent Code*。**已核实**：400 名重复审核者、11,429 次审核、7 个月；批准率
  30.1%→36.8%；按经验十分位累计差距 +14.5pp；行内评论 −22%。

第一条支持人工闸门（自动晋升在真实候选上 0/133），第二条给出它的代价（同一批人越审越松）。
两条一起才是完整的论证，只引第一条是选择性引用。

配套材料 Oversight Has a Capacity（arXiv:2606.08919，未核实）称审核注意力是有限池，闸门
自身的升级策略会耗尽它。应对方向参考 SAP SE（arXiv:2608.00122，未核实）：把审批移到捕获
时刻、由贡献者自己做 —— "the Contributor Client initiates task-adjacent capture with user
approval" —— 同时解决触发问题与审核疲劳。

**现状**：限制章节已补入审核疲劳 +14.5pp 与 GovMem 0/133 两条。

## 论证边界

定位需要明确：**记忆治理只负责记忆域内的治理目标，不覆盖整个 Agent 系统的效果。**

Agent 效果由观测 → 评估 → 优化闭环负责；记忆治理是那个闭环的**输入之一**。这句同时挡掉
两类质疑：

- 「你没测准确率」—— 不在这一层。治理的目标函数是爆炸半径、可归因性、可撤销性。
- 「这不就是审批流吗」—— 审批是手段，捕获经济学是目的。

为什么「用 20 条 vs 3–8 条记忆的消融来质疑治理」是范畴错误：那份消融（arXiv:2603.02473，
未核实）的目标函数是多轮对话 QA 正确性，而治理的目标函数在投毒那一侧。

减损项，不要夸大攻击数字：2026-01 的一次独立复现（arXiv:2601.05504，未核实）发现
"realistic conditions with pre-existing legitimate memories dramatically reduce attack
effectiveness"。更稳妥的论据来自扩散范围：**共享机制会把局部错误扩散为团队级错误**。
治理的依据是对扩散范围的控制，而非攻击成功率的绝对值。

## 关于「行业忽略了共享记忆」：采用可验证表述

不采用「行业忽略了这个轴」这一绝对表述。

支持（认知心理学那一脉确实缺席，均未核实）：CoALA（arXiv:2309.02427）三维是存储／动作空间／
决策流程，无任何 scope 维度；2025–26 最大的综述（arXiv:2512.13564，47 作者）改用
forms/functions/dynamics，仍无 scope 轴；LangChain 自认 "Right now, all memory is specific
for that agent. We have no concept of user-level or org-level memory."

反例（均未核实）：arXiv:2504.15965 的三个基本维度第一个就是 object
(personal/system memory)；Collaborative Memory（Accenture，arXiv:2505.18279）已命名并形式化
该轴；arXiv:2606.24535 有一节字面叫 "5.2 Memory Scopes"；Databricks 称 "The scope is
required on every memory entry request"。而且这个轴 30 年前就有：Walsh & Ungson (1991) 把
记忆定位在 "individual, group and organizational levels"，Nonaka 的 SECI 有明确的本体论轴。
搭桥工作也已存在：G-Memory（NeurIPS 2025 spotlight，arXiv:2506.07398）明说 "inspired by
organizational memory theory"。

建议表述：**scope 轴在组织记忆／治理这一脉成熟，在大家用来教学的认知心理学那一脉缺席 ——
是综合的缺口，不是概念的真空。**

术语别自创。用 memory scope／scoped memory、shared memory tier、collaborative memory、
transactive memory。

## 后续工作的三条判断原则

1. **差异化在准入（curation），不在授权。**
2. **创新在捕获经济学，不在审批流。**
3. **不要用 QA 准确率评判治理；同时不要声称治理提升回答质量。**

第三条包含两个独立约束：避免使用无关指标证明治理有效，也避免对回答质量作出未经验证的承诺。
